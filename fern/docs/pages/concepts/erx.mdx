---
title: eRx safety integration
subtitle: Safety-check a whole electronic prescription in one call
---

`enterprise_erx_safety_check` runs the same safety evaluation as
[`enterprise_safety_check`](/concepts/safety-results) on one prescription: the
lines being prescribed, checked against each other and against the medications
the patient already takes.

## Request shape

```json
{
  "locale": "en",
  "requested_domains": ["ddi", "allergy"],
  "idempotency_key": "RX-7781-v1",
  "erx_payload": {
    "prescription_ref": "RX-7781",
    "lines": [
      {
        "line_ref": "1",
        "input_text": "Warfarin",
        "dose_text": "5 mg",
        "route": "oral",
        "dosage_form": "tablet",
        "frequency_text": "once daily",
        "duration_text": "30 days"
      }
    ],
    "current_medications": [
      { "medication_ref": "home-1", "input_text": "Aspirin" }
    ],
    "patient_context": { "age_years": 67 }
  }
}
```

| Field | Meaning |
|---|---|
| `prescription_ref` | Your identifier for the prescription. Echoed in the response. |
| `lines[]` | The medications being prescribed, 1-50. Each needs a `line_ref` and `input_text`, `sfrx_id`, or both. |
| `current_medications[]` | What the patient already takes. Each needs a `medication_ref` and `input_text`, `sfrx_id`, or both. |
| `patient_context` | Optional [patient context](/concepts/patient-context) for this request only. |
| `requested_domains` | Optional. All six domains when omitted. |

Lines and current medications together hold at most 50 medications, and every
`line_ref` and `medication_ref` must be unique.

Medications are identified exactly as in a safety check (see
[medication identity](/concepts/medication-identity)): `sfrx_id` is
authoritative when you have it, and `dose_text`, `route` and `dosage_form` pick
the registry product when you send a name. A bare name is evaluated as its
default systemic variant and the response says so.

<Note>
`frequency_text` and `duration_text` are accepted so you can send the line as
written, and are returned in `erx.lines[]` so you can show findings beside the
line. They are **not evaluated**: no domain reads frequency or duration today.
</Note>

The payload is closed: an unknown field is refused with
`422 enterprise.safety.request_invalid` naming the field.

## Idempotency

`Idempotency-Key` is required, as for `enterprise_safety_check`. A resend of the
same prescription (same key, same body) returns the original result with
`X-SafeRx-Idempotent-Replay: true` instead of re-evaluating, which matters for eRx
systems that resend on their own timeouts. A resend with the same key but a
changed body is rejected with `409 quota.idempotency.conflict`. Derive the key from
the prescription's identity and version (for example `RX-7781-v1`), so a genuine
resend reuses it and an amended prescription gets a new one.

## Response

A [safety result](/concepts/safety-results) plus an `erx` object:

```json
"erx": {
  "prescription_ref": "RX-7781",
  "lines": [
    {
      "line_ref": "1",
      "sfrx_id": "SRX-010-000334",
      "resolution_status": "resolved",
      "frequency_text": "once daily",
      "duration_text": "30 days"
    }
  ]
}
```

`medications[]` names every evaluated product, lines and current
medications alike, by your `line_ref` or `medication_ref` (as `ref`), and `erx.lines[]`
joins each line to its `medication_ref`, `sfrx_id` and `status`. The same "never reduce
to safe:true/false" rule applies.
