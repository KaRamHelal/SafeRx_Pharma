---
title: Safety results
subtitle: Reading a safety-check result correctly (schema_version 2)
---

<Warning>
Never reduce a safety-check result to a bare `safe: true`/`false` claim. There is no such
field. Read `outcome`, `domains`, `findings` and `review` together.
</Warning>

`POST /safety/checks` and `POST /erx/safety-checks` return an `EnterpriseSafetyCheckResult`.
`GET /safety/checks/{check_id}` returns the same object inside `result`. Every text field is
exactly `{en, ar}`. A value the sources do not state is `null`, never a default.

## The six domains

You choose the domains with `requested_domains`:

| Domain | Covers |
|---|---|
| `ddi` | Drug-drug interactions |
| `pllr` | Pregnancy and lactation |
| `clinical_dose` | Dose for the patient context |
| `food_interactions` | Food and supplement interactions |
| `meal_timing` | Meal-timing instructions |
| `allergy` | Allergy matches and cross-reactivity |

## outcome

The one-line summary.

| Field | Meaning |
|---|---|
| `highest_severity` | The most severe **alert** (`informational`, `low`, `moderate`, `high` or `critical`), or `null` when there is none |
| `action` | That alert's action (see `findings`), or `null` |
| `finding_count`, `alert_count` | All findings, and those of `kind: alert` |
| `blocked` | `true` when any requested domain was not evaluated. Treat the result as incomplete, never as clear |

## medications

There is one entry per request medication, in request order.

| Field | Meaning |
|---|---|
| `ref` | Your `client_medication_id`, or `m1`, `m2`, … |
| `role` | `new` (a target medication) or `current` |
| `status` | `resolved`, `ambiguous` or `unresolved` |
| `selection` | `resolved` only. One of `exact`, `by_id` (you sent an `sfrx_id`), `default_variant` (a bare name with several variants: confirm the product) or `equivalent_product` (one of several identical listings) |
| `product` | `resolved` only: `{sfrx_id, name, generic, strength, form}` |
| `candidates` | `ambiguous` only: up to five products to choose from. Send the chosen `sfrx_id` |
| `reason` | Bilingual. Present when the medication is not resolved |

If no `new` medication resolves, the check is `422 enterprise.safety.target_resolution_required`.
The problem body carries the same `medications` array, with candidates.

## domains

Each requested domain appears exactly once.

| `status` | Meaning |
|---|---|
| `evaluated` | Checked. Findings, if any, are in `findings` |
| `reference_only` | Only general reference applies, for example dose maximums with no patient-specific dose rule. This is **not** "dose checked" |
| `not_applicable` | The check does not apply, for example lactation for a patient who is not lactating |
| `not_enough_context`, `unmapped`, `unavailable`, `failed` | **Not evaluated.** Treat as unknown, not clear. `reason` explains why, and `missing_context` names the fields to send for `not_enough_context` |

Each domain also carries `name`, `finding_count` and the database `release_id` it used.

## findings

| Field | Meaning |
|---|---|
| `finding_id` | Stable id. Quote it with `check_id` when you report a problem |
| `domain`, `kind` | `kind` is `alert`, or `reference` (educational reference, not a warning about this patient) |
| `severity` | `informational`, `low`, `moderate`, `high` or `critical`, mapped from the database's own rating |
| `action` | `urgent_review`, `clarify_first`, `counsel`, `monitor` or `reference`. **Use this, not severity alone, to decide UI treatment** |
| `title` | What was found |
| `explanation` | Why it matters, or `null` |
| `recommendation` | What to do, or `null` |
| `medication_refs` | The `medications[].ref` values involved |
| `subjects` | What the finding is about beyond medicines, for example the declared allergen (`type: allergen`) or the pregnancy population |
| `evidence` | `{grade, source, source_rating}`. `grade` is `primary_label`, `curated_reference`, `secondary_reference`, `local_policy` or `unrated`. `source_rating` is the database's own rating, for example `{value: 3, label: "Major"}` |
| `confidence` | The source's own confidence (0–1), or `null` when the source states none. It is never invented |
| `based_on_context` | The patient-context fields that shaped this finding |
| `review_required` | This finding needs professional review |

## review

| Field | Meaning |
|---|---|
| `required` | Do not rely on the result until it has been reviewed |
| `reasons` | `[{code, message}]`, for example `severe_or_uncertain_signal`, `domain_not_evaluated` or `default_variant_selected` |
| `minimum_reviewer_role` | `qualified_professional`, or `null` |

## patient_context and the rest

- `patient_context` is `{status: applied|none, applied_fields}`. It names the fields that
  were used, never their values. See [Patient context](/concepts/patient-context).
- `release` gives the safety and registry snapshot ids used.
- `disclaimer` is the bilingual educational boundary. Show it with every result.
- `erx` (eRx checks only) lists each prescription line with its `medication_ref`,
  `sfrx_id` and `status`.

## Stored checks

Every result carries a `check_id`, readable for 90 days with `GET /safety/checks/{check_id}`
(see [Stored checks and batches](/concepts/stored-checks-and-batches)). A check stored before
3.0.0, in the retired format, returns `410 enterprise.safety.stored_check_format_retired`. Run
the check again to get a current result.
