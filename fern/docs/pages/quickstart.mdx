## 1. Get an Enterprise key

The existing `enterprise_free` plan is self-service — see
[Developer access](/authentication/developer-portal). Your key is shown
exactly once at issuance; store it securely right away.

## 2. Sign and send a request

Every Enterprise request is signed with `saferx-hmac-sha256-v1`. Send these headers:

| Header | Purpose |
|---|---|
| `X-SafeRx-API-Key` | Enterprise key identifier and signing secret input |
| `X-SafeRx-Timestamp` | UTC timestamp with an explicit offset |
| `X-SafeRx-Nonce` | One-use replay protection value |
| `X-SafeRx-Signature` | Base64url HMAC-SHA256 signature |

The signed canonical message is the uppercase method, escaped path, sorted query, lowercase SHA-256 body digest, timestamp, and nonce joined by newlines. The SDK clients implement this exactly. Never place credentials in source control or logs.


The generated SDK is the safest starting point:

```bash
pip install saferx-pharma
```

```python
from saferx_pharma import SafeRxClient

client = SafeRxClient(
    base_url="https://saferx.online/api/enterprise/v1",
    api_key="YOUR_ENTERPRISE_KEY",
)

result = client.enterprise_safety_check(
    body={
        "locale": "en",
        "medications": [{"input_text": "Augmentin 1g"}],
        "requested_domains": ["ddi", "food_interactions"],
    },
    idempotency_key="integration-check-001",
)
```

## 3. Read the bounded result

A safety response contains `request_id`, `result_id`, `schema_version`, `surface`, `locale`, `summary`, `context_summary`, `signals`, `domain_coverage`, `unavailable_domains`, `limitations`, `review`, `source_provenance`, `display_obligations`, and `correction_anchors`. Never reduce this to a bare `safe: true/false` claim — read `signals` alongside `domain_coverage`/`unavailable_domains` and preserve `review`. See [Safety results](/concepts/safety-results) for the full breakdown.

## 4. Explore the registry

Use `enterprise_registry_autocomplete`, `enterprise_registry_search`,
`enterprise_registry_resolve`, `enterprise_registry_product_detail`, and
`enterprise_registry_ingredients` to resolve and display registry medication
content. See [Registry operations](/concepts/registry) for which one to use.

## 5. Use OCR prescription intake

Prescription OCR is an asynchronous, multi-step Enterprise workflow starting
with `enterprise_ocr_prescription_create` (a `multipart/form-data` upload).
See [OCR prescription lifecycle](/concepts/ocr-lifecycle) for the full
create → read/events → resolve → safety → review sequence.

eRx integrations use `enterprise_erx_safety_check` — see
[eRx safety integration](/concepts/erx).
